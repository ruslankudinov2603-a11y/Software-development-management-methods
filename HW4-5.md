# Домашнее Задание №4

## Доменные Зоны(DDD) С Глоссариями:

### 1. Управление пользователями

**Назначение:** Регистрация, авторизация пользователей и управление их ролями

**Основные функции:**
- Регистрация Клиента
- Авторизация Пользователя
- Создание аккаунта владельца площадки
- Разделение видов пользователей

**Глоссарий:**
- Клиент - Пользователь, который бронирует площадки
- Владелец - Пользователь, управляющий спортивными площадками
- Администратор - Пользователь, контролирующий систему
- Аккаунт - Учетная запись пользователя
- Роль - Набор прав пользователя
- Авторизация - Проверка личности пользователя при входе

### 2. Каталог спортивных площадок

**Назначение:** Хранение и отображение информации о спортивных площадках

**Основные функции:**
- Добавление площадок владельцами
- Просмотр списка площадок
- Отображение адреса и описания
- Отображение вида спорта
- Просмотр стоимости аренды

**Глоссарий:**
- Площадка - Место для занятия спорта, доступное для аренды
- Каталог - Список всех доступных площадок
- Карточка площадки - Основная информация о площадке
- Вид спорта - Футбол, Баскетбол, Волейбол и другие виды спорта
- Адрес - Местоположение площадки
- Владелец площадки - Пользователь, разместивший площадку

### 3. Управление расписанием и ценами

**Назначение:** Управление свободным временем и стоимостью аренды площадок

**Основные функции:**
- Создание временных слотов
- Изменение расписания
- Установка стоимости аренды
- Отображение свободного времени
- Обновление доступности после бронирования

**Глоссарий:**
- Расписание - График доступности площадки
- Временной слот - Конкретный промежуток времени для аренды
- Доступность - Состояние временного слота
- Свободный слот - Время, которое можно забронировать
- Стоимость Аренды - Цена за выбранный слот
- Пересечение слотов - Наложение двух временных промежутков

### 4. Бронирование

**Назначение:** Создание и подтверждение бронирований спортивных площадок

**Основные функции:**
- Выбор свободного временного слота
- Проверка его доступности
- Создание бронирования
- Расчет итоговой стоимости
- Подтверждение бронирования
- Просмотр своих бронирований

**Глоссарий:**
- Бронирование - Резервирование площадки на определенное время
- Статус бронирования - Состояние бронирования
- Подтверждение - Уведомление об успешном бронировании
- Итоговая стоимость - Сумма за выбранный временной слот
- Клиент - Пользователь, оформивший бронирование

### 5. Администраторы и Модераторы

**Назначение:** Контроль пользователей и корректности информации на платформе

**Основные функции:**
- Проверка добавленных спортивных площадок
- Модерация информации
- Управление пользователями
- Блокировка аккаунтов при нарушении правил
- Контроль корректной работы приложения

**Глоссарий:**
- Модерация - Проверка информации перед публикацией
- Проверенная площадка - площадка, прошедшая модерацию
- Блокировка - Ограничение доступа к сервису
- Статус Модерации - Результат проверки площадки
- Администратор - Пользователь, контролирующий платформу

## Критический путь MVP в формате BDD:

**MVP - Бронирование спортивной площадки клиентом**

### Сценарий1. Успешное бронирование

**Дано:**
- Пользователь авторизован в приложении
- Пользователь выбрал спортивную площадку
- На выбранную дату есть свободный временной слот
- Стоимость выбранного слота составляет 2000 рублей
- Слот еще не забронирован другим пользователем

**Когда:**
- Пользователь выбирает свободный временный слот
- Проверяет информацию о бронировании
- Нажимает кнопку "Подтвердить Бронирование"

**Тогда:**
- Система повторно проверяет доступность слота
- Создается новое бронирование
- Статус бронирования устанавливается в "Подтверждено"
- В расписании площадки выбранный слот становится занятым
- Пользователь видит сообщение "Бронирование успешно подтверждено"
- Пользователь видит информацию о площадке, дате, времени и итоговой стоимости

### Сценарий2. Неуспешное бронирование

**Дано:**
- Пользователь авторизован в приложении
- Пользователь выбрал спортивную площадку
- При просмотре расписания выбранный слот был свободен
- До подтверждения бронирования другой пользователь успел забронировать этот слот

**Когда:**
- Первый пользователь нажимает кнопку "Подтвердить Бронирование"

**Тогда:**
- Система повторно проверяет доступность слота
- Обнаруживается, что выбранный слот уже занят
- Новое бронирование не создается
- Система показывает сообщение "К сожалению, это время уже занято. Выберите другой слот"
- Пользователь может вернуться к расписанию и выбрать другое время

## API №2. Создание бронирование

**Пример Запроса+JSON тело запроса:**

```http
POST /api/v1/bookings
Authorization: Bearer <access_token>
Content-Type: application/json
```

```json
{
  "slotId": 501
}
```

**JSON при успешном бронирование:**

```json
{
  "booking": {
    "id": 701,
    "userId": 15,
    "facilityId": 101,
    "slotId": 501,
    "date": "2026-11-10",
    "startTime": "18:00",
    "endTime": "19:00",
    "totalPrice": 2000,
    "currency": "RUB",
    "status": "confirmed"
  },
  "message": "Бронирование успешно подтверждено"
}
```

**JSON при ошибке:**

```json
{
  "error": {
    "code": "SLOT_ALREADY_BOOKED",
    "message": "Выбранное время уже занято. Выберите другой слот."
  }
}
```

## 3. Обоснование выбора технологий для MVP

| Технология | Для чего используется | Почему выбрана |
|---|---|---|
| React | Веб-интерфейс | Позволяет создать удобный интерфейс для разных ролей пользователей |
| Python | Серверная разработка | Простой и понятный язык, позволяющий быстро реализовать бизнес-логику |
| FastAPI | REST API | Позволяет быстро создавать API и обрабатывать запросы приложения |
| PostgreSQL | База данных | Подходит для хранения связанных данных и работы с бронированиями |
| Nginx | Веб-сервер | Обрабатывает HTTPS-запросы и передаёт их серверу приложения |
| Gunicorn / Uvicorn | Запуск backend-приложения | Обеспечивает работу серверной части приложения |

Для MVP выбрана монолитная архитектура, так как она позволяет быстрее разработать и запустить первую версию приложения.
